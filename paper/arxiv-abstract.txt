Agent skill registries screen what they publish. OpenClaw's own security team reported that its scanners overlap on at most 10.4% of combined positives, and that 81.9% of flagged skills are caught by one scanner alone. We take that as given, and suggest the open question is not which scanner is right but which question is being asked: each signal answers a form of "is this skill malicious?", which is what it was built for. A second question, "is this action permitted on this machine, by this operator, right now?", is not one any of them is designed to express.

We report three measurements over 66,192 public ClawHub skill versions and a live agent. First, 705 skills across 135 distinct publishers that every scanner and the registry's own judge rate clean nonetheless instruct an action named as prohibited by CIS Control 2.7 and NIST SP 800-53 CM-11. A hand audit of 100 puts our detector at 92% precision (95% CI 84.8-96.5) and found no marker of malicious intent. One publisher contributes 506 of the 705, so we report the distribution alongside the count. This measurement is reproducible from public artifacts. Second, of 93 commands a live agent executed while following real skill documentation, 36.6% carried a consequence class absent from every code block of that document. Third, we set out what sits outside each layer's view, including our own.

We offer one design for a control point at that gap: a deterministic resolver with no model in the decision path, feeding a per-(resource, class) trust ledger whose promotion thresholds derive from an operator's stated risk tolerance. Ten clean approvals cannot exclude a true failure rate as high as 25.9% at 95% confidence. We release a 64-case benchmark for action-level governance; ours resolves 52% of it.
